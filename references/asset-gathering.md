# 소재 수집

소재 활용 우선순위: **제품 1차 원본 소재 > AI 생성 소재 > 일반 인터넷 소재**. 1차 원본 소재(실제 UI 화면, 실제 결과물, 실제 통계 데이터)는 설득력의 핵심 원천이며, AI 생성은 주로 분위기 연출, 배경, 마스코트 캐릭터, 3D 로고 렌더링에 사용합니다.

모든 소재는 `조사_노트.md`에 등록 관리합니다: 파일명 → 출처(로컬 경로 또는 URL) → 사용될 씬 번호.

---

## 1. 제품 1차 원본 소재

### 로컬 저장소 / 기술 문서
- README, 디렉터리 구조, 목차를 먼저 분석하여 실제 수치(문서 수, 이미지 수, 총 글자 수, 모듈 수 등)를 집계합니다. 집계 방식과 결과는 조사 노트에 기록하고, 영상에 노출되는 수치는 오직 실제 집계된 데이터만 사용합니다.
- 문서 내 삽입 이미지를 일괄 수집하고, 문서별로 밀착 시트(Contact Sheet)를 생성하여 선별합니다:

```bash
python3 scripts/images.py grab "<저장소경로>/실전프로젝트" "<저장소경로>/모델소식" -o /tmp/imgs
python3 scripts/images.py sheet /tmp/imgs            # 문서별로 _sheet_<번호>.jpg 생성 후 한눈에 검토
python3 scripts/images.py crop out/pick.jpg /tmp/imgs/ab12c_03.png /tmp/imgs/9f0e1_11.png
python3 scripts/images.py prepare /tmp/imgs/ab12c_03.png public/works/hotpulse.jpg
```

- **각 이미지의 전후 맥락 검증**: 이미지 앞뒤 문맥에서 무엇을 설명하고 있는가? 이 제품으로 직접 만든 것인가, 아니면 공식 데모/타사 비교/단순 참고 사례인가? 불확실한 이미지는 절대 사용하지 않습니다.
- 흔한 캡처 문제점: 폰 화면 3개를 이어 붙인 멀티스크린, 빨간 강조 박스가 쳐진 이미지, 반쯤 잘린 이미지 등. "작업 중간 과정 샷"이 아닌 "완성도 높은 최종 결과물 샷"을 선택합니다.

### 공식 홈페이지 / 라이브 서비스
- `firecrawl scrape`로 카피 문구와 레이아웃 구조를 가져오고, **페이지 내 모든 작업물 이미지 URL을 함께 추출**합니다. 커뮤니티 게시글, 공식 가이드, 커리큘럼 소개 페이지에는 고화질 실사 캡처가 많이 포함되어 있으므로, 로그인 여부를 결정하기 전에 먼저 전체 수량을 파악합니다.
- 실제 인터페이스 캡처는 레이어별로 분해 재구성(Rebuilding)할 수 있습니다: 주요 카드, 버튼, 리스트를 React 컴포넌트로 다시 구현하면 정적 스크린샷보다 훨씬 풍부한 모션 연출이 가능합니다 (단, 재구성은 스크린샷의 완성도를 높이는 보조 수단이며 실제 캡처를 대체할 수는 없습니다).

### 실제 화면 4K 고화질 캡처
- **`scripts/shot.py` 최우선 사용** (Playwright 기반, 모든 AI 도구에서 공통 구동 가능): `python3 scripts/shot.py <URL> <이름> --scroll 0 1400` 명령으로 1920×1080 @2x 해상도로 캡처하여 3840×2160 크기의 `out/shots/<이름>-<번호>.jpg`를 확보합니다. `--hide`로 불필요한 배너/플로팅 바의 CSS 선택자를 숨기고, `--eval`로 세부 DOM 정리를 수행하며, `--tall 4200 --scale 1.25`로 긴 페이지 전체를 캡처합니다.
- **로그인이 필요한 경우**: 먼저 백그라운드로 `python3 scripts/shot.py --login <URL>`을 실행하여 실제 GUI 브라우저 창을 띄웁니다. 사용자에게 **해당 창**에서 로그인(QR코드, 소셜 로그인 등)하도록 요청한 뒤 창을 닫게 합니다. 로그인 세션은 `out/.browser-profile/`에 보존되어 이후 모든 `shot.py` 캡처에 자동 적용됩니다.
- **Chrome DevTools MCP 활용 가능**: `new_page` 열기 → `emulate`로 `viewport: "1920x1080x2"` 지정 → `evaluate_script`로 화면 정리 → `take_screenshot`(`format: "jpeg", quality: 92`)으로 3840×2160 캡처.
- **AI 도구 내장 브라우저로 캡처하지 말 것**: 뷰포트 크기가 900px 전후의 1배율에 불과하며, 고해상도를 시뮬레이션할 경우 타일 형태로 깨져 캡처됩니다.
- **사용자가 이미 내장 브라우저에 로그인한 경우**: 다시 로그인할 필요 없이 `scripts/snapshot.js`를 브라우저 콘솔에서 실행하여 스타일이 인라인된 독립 HTML을 추출한 뒤, `python3 scripts/snapshot.py <파일> <이름>`으로 로컬 Chromium에서 3840×2160 해상도로 재렌더링합니다.
- **화면 정리 원칙**: 캡처 전 프로모션 배너(할인, 갱신 유도 띠배너), 우측 플로팅 퀵메뉴, 하단 쿠키 바 등을 숨기고 주요 영역으로 스크롤하여 캡처합니다.
- **다양한 기능을 보여줄 때는 상세 페이지 대신 목록/허브 페이지를 캡처**: "수많은 기능(100+ 로드맵, 30개 프로젝트)" 자체가 핵심 강점일 때는 개별 상세 화면 하나보다 방대한 리스트가 스크롤되는 목록 화면을 보여주는 것이 훨씬 압도적인 설득력을 제공합니다.
- **비율 유지 필수**: Tailwind의 기본 `max-width: 100%` 속성으로 인해 이미지가 찌그러지지 않도록 템플릿의 `BrowserFrame.tsx`를 사용하고 원본 가로세로 비율을 엄격히 준수합니다.

### 소셜 플랫폼 사례 (X / 트위터 등)
공식 자료가 부족하고 유저 커뮤니티에 사례가 흩어져 있는 경우:

- **원문 게시물 추적**: 2차 인용 기사는 단서로만 활용하고, 인용 링크나 스크린샷의 ID를 추적해 원문 작성자의 트윗을 찾습니다. 원본 게시물이 확인되지 않은 사례는 사용하지 않습니다.
- **원본 미디어 다운로드**: `python3 scripts/xgrab.py <트윗ID...>`로 fxtwitter 공개 API를 호출하여 로그인 없이 원본 고화질 이미지(`name=orig`) 및 원본 비디오를 직접 다운로드합니다.
- **저작권 및 출처 표기**: 각 사례 화면 위에 `@작성자 · 날짜`를 명시하고, 영상 엔딩에 전체 출처를 나열합니다.

### 수치 데이터
- GitHub: `gh api repos/<소유자>/<저장소> --jq '.stargazers_count'`.
- 기타 플랫폼 수치(팔로워 수, 유저 수 등)는 공식 페이지 또는 사용자 제공 수치를 기준으로 출처를 명시합니다.

## 2. 아이콘 및 로고

```bash
npm pack simple-icons && tar xzf simple-icons-*.tgz            # package/icons/<slug>.svg, 단색 SVG, 렌더링 시 색상 지정
npm pack @lobehub/icons-static-svg && tar xzf lobehub-*.tgz    # 최신 AI 제품군 아이콘 풀세트 (Claude Code, Codex, Cursor 등)
```

- 다운로드 후 아이콘 벽을 렌더링하여 명칭, 색상, 어두운 배경에서의 가시성(필요 시 `filter: invert(1)` 적용)을 검증합니다.
- 제품 자체 로고는 공식 저장소나 웹사이트의 SVG/고화질 PNG 원본을 활용하며, 3D 질감이 필요한 경우 이미지 생성 AI로 원본 로고를 참조하여 렌더링합니다.

## 3. AI 생성 이미지

용도: 스타일 샘플 프레임, 앰비언트 배경, 마스코트 캐릭터, 3D 로고, 콘셉트 일러스트. AI 도구의 이미지 생성 기능 활용. 생성 기능이 없는 경우 CSS 그라데이션, SVG, `@remotion/noise` 등 코드로 배경과 장식을 구현합니다.

- 프롬프트 작성 시 주의사항: 화면비(16:9 / 9:16), 스타일 키워드, 조명, 구도, **텍스트를 배치할 충분한 여백(Negative Space) 확보**, 프롬프트에 글자를 넣지 말 것(텍스트는 코드에서 직접 타이포그래피로 구현).
- 캐릭터(Q버전/마스코트): 먼저 메인 시그니처 포즈 1장을 완성한 후, 이를 참조 이미지로 고정하고 표정과 동작만 변경하여 동일 캐릭터의 일관성을 유지합니다.

## 4. 폰트 (타이포그래피)

- 본문 폰트: 시스템 기본 고딕(Pretendard, 맑은 고딕, Noto Sans CJK 등)을 활용하여 가독성을 극대화합니다.
- 타이틀 폰트: 분위기에 맞춰 상업적 이용이 가능한 무료 라이선스 폰트를 선택합니다.
  - 테크/기하학적 느낌: 에스코어 드림, 프리텐다드 블랙, 딜라이트 볼드 등
  - 개성 있고 젊은 느낌: 배달의민족 한나체, 티머니 둥근바람 등
  - 레트로 픽셀: 둥근모꼴 등 비트맵 폰트
- 폰트 파일은 `fonts-src/`에 배치하고 `fonts.json`에 등록한 뒤 `npm run fonts`로 서브셋을 생성합니다. 스크립트에서 **글자 누락**이 보고되면 대체 폰트를 적용하거나 카피 문구를 수정합니다.

## 5. 배경음악 및 효과음 소싱

- **ElevenLabs** (API 키 제공 시 최우선): 씬별 맞춤 작곡, 화면 맞춤 효과음, 고품질 v4 내레이션 지원 (`references/voiceover.md` 및 `references/music-and-beats.md` 참조).
- **Mixkit** (상업적 이용 무료, 출처 표기 불필요): `scripts/music.py`를 통해 검색 및 다운로드:

```bash
python3 scripts/music.py search music cinematic trailer electronic uplifting   # 제목/ID/재생시간 검색
python3 scripts/music.py search sfx whoosh impact riser typing glitch click
python3 scripts/music.py get music 726 614 -o /tmp/music
python3 scripts/music.py get sfx 790 2531 1486 -o audio-src
```

  자주 사용하는 효과음 키워드: `whoosh`, `impact`, `riser`, `typing`, `click`, `glitch`, `transition`, `pop`, `notification`.
- **합성 오디오 (`audiolib.py`)**: 저음 임팩트 `sub_boom`, 비프음 `blip`, 카드 넘김 `flick`, 룸 톤 `room_tone`. **합성 지속음(drone)을 음악 아래에 무분별하게 깔지 마세요** (음악의 조성과 충돌하여 불협화음을 유발함).

## 6. 비디오 클립 소재

- 제품 시연 녹화본: 사용자가 제공한 원본을 우선 사용합니다. 없는 경우 브라우저 툴로 실제 웹서비스를 조작하는 화면을 녹화하거나 React 코드로 애니메이션 UI를 재구성합니다.
- 외부 비디오 클립은 사용자가 명시적으로 허락한 경우에만 사용합니다.
