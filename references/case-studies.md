# 사례 회고

이 문서는 본 도구를 사용하여 실제로 제작·납품한 5편의 홍보 영상을 기록한 회고록입니다. 완성 영상과 프로젝트 파일은 저장소에 포함되지 않지만(대용량 및 개별 소재/API 키 포함), 향후 프로젝트에 유용한 핵심 교훈을 정리했습니다: 각 영상에서 해당 스타일을 선택한 이유, 사용자가 제기한 피드백, 그리고 최종적으로 문제를 해결한 방법입니다.

이 문서를 읽는 목적은 '방법론'을 학습하기 위함입니다. **그 어떤 영상의 색상, 레이아웃, 카메라 워크, 이펙트도 그대로 베끼지 마세요.** 새로운 제품은 반드시 그 제품만의 해답을 찾아야 합니다.

---

## 1. 바이브 코딩(Vibe Coding) 튜토리얼 홍보 영상

- **제품**: 무료 AI 코딩 입문 튜토리얼 시리즈.
- **최종본**: 다크 무비 트레일러(시네마틱) 스타일, 78초, 4K60, 웹 플레이어 버전 포함.
- **피드백 이력**: 4차례 피드백. 1차 버전은 빠른 컷 전환 0.45초, 정보 씬 3.6초로 구성했으나 "너무 빨라서 시청자가 따라가지 못한다"는 피드백을 받아 `AGENTS.md`의 "템포 하한선" 규칙이 탄생했습니다. 오프닝 음악이 마디 중간에서 어색하게 시작되고 저음 합성 드론 사운드가 덧대어져 "음악이 이상하다"는 지적을 받아 "마디 라인 진입, 드론 사운드 지양" 규칙을 정립했습니다. 또한 "영상 전체에 전체 URL 주소가 한 번도 나오지 않는다"는 지적에 따라 클라이맥스 구간에 전체 URL을 필수로 배치하게 되었습니다.
- **학습 포인트**: 실제 앱 UI 화면을 여러 레이어로 분리하여 React 컴포넌트로 재구성하고, 화면 위에서 블록처럼 자라나듯(Grow) 등장시키는 연출이 단순 정적 스크린샷보다 훨씬 생동감 있습니다.

## 2. 프로그래밍 내비게이션(커뮤니티) 홍보 영상

- **제품**: 학습 로드맵, 실전 프로젝트, 면접 기출문제, 커뮤니티를 제공하는 개발자 학습 플랫폼.
- **최종본**: 라이트 톤 아이소메트릭(등각 투영) 3D 지도 스타일(SVG 코드로 그린 가상 도시), 60초, 4K60 + 1080p60 + 웹 버전.
- **피드백 이력**: 2차 버전은 "템포가 느림, 실제 스크린샷 부족, 배경음악 불일치" 피드백에 따라 전체적으로 전면 재작업했습니다. 재작업 후 페인포인트 오프닝으로 변경하고 3.9초 만에 음악 드롭(비트 폭발)으로 진입하도록 개선했으며, 로그인 후 10장의 4K 실제 페이지 스크린샷을 확보하여 프로젝트 숏컷 몽타주를 2비트마다 전환시켰습니다. 사용자는 또한 로드맵 섹션에 단일 상세 페이지만 보여주기보다 "로드맵 목록 전체를 보여주어야 한다(수량 자체가 강력한 셀링포인트)"고 지적했습니다. 3차 버전부터 배경음악, 효과음, 내레이션 전반을 ElevenLabs로 제작했습니다.
- **학습 포인트**: ElevenLabs로 씬별 맞춤 작곡을 진행한 후, `music` 슬라이싱 테이블을 활용해 마디 라인에서 곡 길이를 자연스럽게 연장했습니다. 내레이션은 보이스 라이브러리의 Haoran(`pU9NaAwkoR3v0Mrg3uKz`, '광고' 카테고리, 깊고 매력적인 톤)을 선정했으며, 3개 후보 중 유일하게 오프닝 문장을 속도 배속 없이 소화했습니다. 웹사이트 URL 발음이 단독으로는 맞았으나 음악에 묻혀 "점 CM"으로 오인되는 문제가 있어, 해당 문장의 duck(배경음 감소)을 깊게 하고 동시 발광 효과음을 줄이며 대본 `say` 필드에 대문자 "C N"으로 명시하여 안정화했습니다.

`timing.json` 내 음악 및 내레이션 실제 작성 예시 (발췌):

```json
{
  "beat": 0.5453, "bar": 2.1812, "drop": 4.3624, "musicOffset": 3.3696,
  "music": [
    {"at": 0, "from": 3.3696, "to": 55.7184},
    {"at": 52.3488, "from": 46.9936, "to": 51.356},
    {"at": 56.7112, "from": 55.7184, "to": 58.56}
  ],
  "voice": {
    "voiceId": "pU9NaAwkoR3v0Mrg3uKz", "model": "eleven_v4", "language": "zh",
    "settings": {"stability": 0.45, "similarity_boost": 0.75, "use_speaker_boost": true},
    "rmsDb": -13, "duckDb": -9, "gain": 1.0,
    "lines": [
      {"id": "hook", "at": 0.35, "end": 4.25, "text": "어디서부터 시작할지 막막한가요? 프로젝트에 내세울 강점이 없나요?"},
      {"id": "brand", "at": 4.65, "end": 8.6, "text": "프로그래밍 내비게이션, 로드맵 학습부터 포트폴리오 프로젝트, 취업 합격까지!"}
    ]
  }
}
```

`music` 테이블의 의미: 영상 `at`초 시점부터 음원의 `from`~`to` 구간을 재생합니다. 두 번째 구간은 중간 2마디를 한 번 더 반복하여 음악이 정확히 60초를 채우도록 맞췄으며, 모든 접합점은 마디 선 위에 배치했습니다.

## 3. 면접덕(개발자 면접 문제은행) 홍보 영상

- **제품**: 개발자 면접 대비 문제풀이 플랫폼.
- **최종본**: 흑백 열혈 만화 스타일(시그니처 오리 노란색 포인트 컬러), 2차 버전 53.7초, 4K60 + 1080p60 + 웹 버전.
- **피드백 이력**: "템포 느림, 실제 스크린샷 부족, 예시 문제가 비현실적임, 음악 불일치" 피드백으로 전면 수정. 오프닝에서 사이트 내 조회수가 가장 높은 실제 기출문제 4개를 연속으로 직격 배치하고, ElevenLabs 맞춤 작곡(두 번의 드롭 + 중간 완화 구간, 완화 구간에 해설 내레이션 배치)을 적용했습니다. 내레이션은 제작자 본인의 복제 음성을 사용했는데, 해당 보이스가 `eleven_multilingual_v2`로만 학습되어 있어 stability 0.5에서 발음 왜곡이 발생하여 0.85로 높여 안정화했습니다.
- **학습 포인트**: AI로 생성한 만화 컷에 Real-ESRGAN 4배 업스케일을 적용해야 4K 화면에서 잉크 펜선이 뭉개지지 않습니다. 공식 공개 API를 통해 283개의 실제 문제 카테고리 아이콘을 수집하여 아이콘 월을 구성했습니다. 스크린샷을 만화 먹선 프레임 컨테이너에 넣어 줌인/아웃 연출을 가미하여 만화 스타일과 실제 UI 스크린샷의 진정성을 모두 확보했습니다. 또한 음성 재녹음으로 발음을 개선했습니다 (`references/voiceover.md` 5절 참조).

## 4. 위피(YuPi) AI 내비게이션 홍보 영상

- **제품**: AI 도구 및 리소스 큐레이션 웹사이트.
- **최종본**: 밝고 산뜻한 수중 Q버전(로고 기반 물고기 마스코트 + 스티커 아웃라인), 66.3초, 4K60 + 1080p60 + 인스트루멘털(음악 전용) 버전 + 웹 버전.
- **피드백 이력**: 무려 5차례 수정이 이루어져 가장 문제가 많았고, 그만큼 가장 많은 규칙을 남긴 사례입니다:
  - 오프닝 지연: 페인포인트 구간을 9.3초에서 4초로 압축.
  - 실제 스크린샷 부재: 각 카테고리마다 브라우저 윈도우 프레임을 사용해 실제 웹페이지 스크롤 연출. 회원가입/로그인이 필요한 가이드 문서는 브라우저 로그인 후 DOM 스냅샷 재렌더링으로 4K 스크린샷 확보 (`snapshot.js`가 이때 개발됨).
  - 음악 선정 반려: 1차(아동용 'Kids'), 2차(경쾌한 팝) 모두 부적합 판정. 3차에서 완전히 다른 장르 6곡을 내레이션과 믹싱해 샘플을 제시한 끝에 Mixkit의 'Better Times are Coming'으로 확정. 교훈: 음악은 그림체가 아니라 타깃 관객과 제품 성격에 맞춰야 함.
  - 이미지 가로 왜곡: Tailwind의 `img { max-width: 100% }` 속성이 스크린샷을 비정상적으로 압축시켰던 문제를 템플릿 `index.css`에서 수정.
  - 브랜드명 발음 오류 + 잔향/에코: `multilingual_v2`가 브랜드명을 잘못 발음하고 문장 끝에 90~360ms의 에코 잔향이 남았던 문제; `eleven_v3`로 정확히 읽은 뒤 음성 변환(STS)으로 본인 음색을 입혀 해결 (`voice.sts`와 `voice.keywords` 기능이 이때 추가됨).
- **주의사항**: 이 프로젝트는 구버전 템플릿 기반이어서 내레이션을 `vo` 파이프라인으로 생성하지 않았습니다. 향후 프로젝트는 반드시 템플릿의 `elevenlabs.py vo`를 사용하고 별도 스크립트를 작성하지 마세요.

## 5. Claude Fable 5.5 모델 프리뷰 홍보 영상

- **제품**: 공식 출시 전 커뮤니티에서 비공식 유출 루머로 화제가 된 AI 모델 버전.
- **최종본**: 기밀 유출 문서 스타일(차콜 블랙 + 크라프트지 텍스처 + 오렌지 포인트), 60초, 4K60 + 1080p60 + 웹 버전. 본 영상은 '사전 유출 미리보기(Sneak Peek)' 콘셉트로 전편에 '공식 미확인' 표기를 유지했습니다.
- **피드백 이력**: 3차례 피드백. 제작자 본인 복제 음성의 억양이 부자연스럽다는 지적에 따라 라이브러리 음색 Haoran으로 교체 후 일치율 1.000 달성. 오프닝의 모호한 수수께끼식 연출을 개선하여 "정체 → 발견 경위 → 검증 과정 → 실제 결과물 → 공식 미확인 주의사항"의 명확한 인과관계 스토리라인으로 개편. 오프닝 4초에 3개 샷, 2초에 초점 2개를 넣었던 과밀 템포를 첫 4초 2개 화면, 각 초점당 최소 1.4초 유지로 완화.
- **학습 포인트**: 사례 자료를 X(구 트위터) 원문 게시물까지 추적하여 `xgrab.py`로 원본 고화질 이미지/영상을 다운로드했습니다. 각 사례마다 `@작성자 · 날짜`를 표기하고 영상 말미에 전체 출처를 명시했습니다. 작곡 시 고요한 분위기 구간이 누락되었을 때 `audiolib.muffle`로 로우패스 필터를 걸어 공식 발표 전의 적막감을 훌륭하게 연출했습니다.

## 공통 핵심 원칙

5편의 영상 피드백을 종합했을 때, 사용자가 가장 중요하게 생각하는 요소는 다음과 같습니다:

1. **오프닝은 빨라야 한다.** 거의 모든 영상의 1차 피드백은 "시작이 느리다"였습니다. 페인포인트나 핵심 강점이 3초 이내에 터져 나와야 합니다.
2. **진짜 결과물과 화면을 보여주어야 한다.** 코드로 예쁘게 다시 그린 카드나 AI 생성 이미지가 아무리 화려해도 실제 UI 스크린샷과 실제 결과물을 대체할 수 없습니다.
3. **음악은 사용자가 직접 귀로 듣고 결정해야 한다.** AI가 임의로 고른 음악은 기각될 확률이 가장 높으므로, 미리 청취 샘플을 제공하는 것이 가장 효율적입니다.
4. **기교보다 명확한 설명이 우선이다.** 비전문가가 이해하지 못하는 오프닝은 전문가 입장에서 아무리 참신해도 실패한 연출입니다.
5. **복제 음성(Voice Clone)이 항상 최선은 아니다.** 본인 음성 클론은 억양 왜곡이나 부정확한 발음이 발생하기 쉬우므로, 항상 전문 보이스 라이브러리 음색과 함께 청취 비교 후 결정해야 합니다.
