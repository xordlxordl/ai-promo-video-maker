# 요구사항 인터뷰

요구사항 확정 전에는 반드시 사용자에게 먼저 질문해야 합니다. 목표: 최소한의 질의응답으로 영상 제작에 영향을 미치는 모든 결정을 한 번에 명확히 파악하여 `요구사항_확인서.md`로 정리하는 것입니다.

## 질문 방식

- 사전 조사를 먼저 완료한 후 질문합니다. 질문과 선택지는 **해당 제품에 맞춰 구체화**해야 합니다 (예: "클라이맥스 씬에서 무엇을 보여줄까요?"가 아니라 "클라이맥스 씬에서 AI가 말 한마디로 가계부 앱을 뚝딱 만들어내는 모습을 보여줄까요?").
- 구조화된 질문 도구(Cursor의 `AskQuestion`, Claude Code의 `AskUserQuestion`, 없는 경우 본문에 번호 매긴 선택지 나열)를 사용합니다. 라운드당 5~8개 질문으로 보통 두 라운드 내에 완료합니다. 각 항목의 첫 번째는 추천 옵션으로 `(추천)`을 붙이고 이유를 한 줄 덧붙입니다.
- 1라운드 진행 전 `doctor.py`를 먼저 실행하여 사용자의 ElevenLabs 키 유무, 캡처 가능 여부를 파악한 뒤, 오디오와 스크린샷 질문의 선택지를 실제 환경에 맞게 제공합니다.
- 사용자가 "네가 알아서 결정해"라고 답하면 직접 결정하되, `요구사항_확인서.md`에 결정 내용과 이유를 명시하여 확인 단계에서 확인할 수 있도록 합니다.
- 사용자가 자유 텍스트로 추가한 내용(예: "라이선스 문제는 신경 쓰지 않음", "내 목소리는 불필요함")은 원문 그대로 `요구사항_확인서.md`에 기록합니다.

## 0단계: 제품 출시 상태가 불분명할 때 포지셔닝 먼저 질문

사전 조사 결과 제품에 **공식 출처가 없는 경우**(아직 미출시, 그레이마켓 루머만 존재, 버전 불일치 등)에는 1라운드에 앞서 이 항목을 단독으로 질문합니다. 이후 모든 소재와 팩트 활용 방식이 결정되기 때문입니다:

| id | 질문 | 선택지 |
|---|---|---|
| direction | 아직 공식 출시되지 않았는데, 영상을 어떻게 제작할까요? | 스타일, 음악, 프레임워크를 미리 준비해두고 공식 발표 당일 공식 데이터를 채워 넣음(추천) / 이미 출시된 안정 버전으로 변경 제작 / 동일 시리즈의 기출시 모델로 제작하고 엔딩에 후속작 티저 추가 / 지금 '미리보기' 형태로 제작: 유저 실측 리뷰만 사용하고 출처 표기, 전편에 '공식 미확인' 워터마크 표시 / 사용자 본인이 신뢰할 만한 소스를 보유하고 있음 |

'미리보기'를 선택한 경우: 화면에 "유저 실측 데이터 · 공식 미확인" 문구를 상시 표시하고, 공식 벤치마크 점수/가격/공식 기능 표현은 일절 사용하지 않으며, 엔딩에 공식 뉴스룸 스크린샷으로 "공식 발표 대기 중"임을 안내합니다. 작업 시작 후 반나절 이상 지난 뒤 납품할 때는 공식 상태와 새로운 사례를 다시 확인합니다.

## 1라운드: 방향성 설정

| id | 질문 | 대표 선택지 (제품에 맞게 변형) |
|---|---|---|
| deliverable | 결과물 형식 | MP4 + 동일 소스 웹 플레이어 버전(추천) / MP4만 필요 / 웹 버전만 필요 |
| format | 화면비 및 재생 시간 | 16:9 약 45~60초(추천) / 30초 숏컷 / 70~90초 롱버전(사유 명시 필요) / 9:16 숏폼 우선 / 가로+세로 듀얼 버전 |
| hook | 오프닝 훅 (3초 이내; 배경을 전혀 모르는 사람도 첫 문장을 이해할 수 있어야 함) | 페인포인트 접근: 타깃 유저의 가장 절실한 페인포인트 2~3개를 연속 타격(추천, 제품 맞춤 구체화) / 핵심 강점 접근: 첫 1초에 가장 놀라운 수치나 결과물 제시 / 결과 중심 접근: 최종 결과물을 먼저 보여주고 역순 전개 |
| audience | 주요 타깃 시청자 | 제품에 맞는 2~4개 유저 그룹 나열 + 범용 커버리지 |
| style | 비주얼 스타일 방향 | **제품 맞춤 3~4개 방향, 스타일 샘플 프레임 첨부** (아래 설명 참조) |
| story | 내러티브 구조 | `references/style-directions.md`의 스토리 메뉴에서 가장 적합한 2~3개를 골라 이 제품에 맞게 구체화. 각 선택지에 "내레이션 첫 문장"을 명시하여 비전문가가 이해할 수 있는지 판단 |
| hero | 클라이맥스(히어로) 씬 | 제품 가치를 가장 극대화하여 보여줄 수 있는 한 장면, 구체적 방안 2~3개 제시 |
| audio | 사운드 구성 | **ElevenLabs 계정이 있는 경우**: 씬별 맞춤 작곡 + v4 내레이션(추천) / 음악 비트 싱크 + 큰 자막 / 사용자 본인 녹음 / 엔딩 한 문장만 본인 음성. `elevenlabs.py quota` 및 `voices`로 사전 확인. **계정이 없는 경우**: 음원 라이브러리 비트 싱크 + 큰 자막(추천) / 사용자 본인 녹음 / ElevenLabs 가입 후 `.env`에 키 등록. **음색은 이 라운드에서 확정하지 않음**: 내레이션 대본 작성 후 3개 후보(본인 클론 보이스 포함)로 각 3문장 샘플을 `工程/out/音色候选/`에 생성하여 사용자가 청취 후 결정 |

### 스타일 샘플 프레임 (style 항목 필수 진행)

1. `references/style-directions.md`에서 서로 완전히 다른 3~4가지 방향을 선택하거나 창작합니다. 최소 하나는 파격적인 스타일(SD 캐릭터/손그림/픽셀 아트/점토/네온 등)을 포함해야 하며, 4개 모두 "어두운 테크풍"의 변형이어서는 안 됩니다.
2. 각 방향마다 16:9 샘플 프레임을 1장씩 생성합니다: 제품의 실제 이름, 실제 카피 문구, 대표 요소를 배치하여 "내 제품에 적용하면 어떤 모습일지" 사용자가 체감할 수 있게 합니다. 이미지 생성 도구(Cursor `GenerateImage`, Codex 등)가 있다면 활용하고, 없다면 HTML/CSS로 1920×1080 페이지를 제작한 뒤 스크린샷 스크립트로 캡처합니다.
3. 시트 스크립트로 하나로 이어 붙이거나 개별 이미지를 답변에 첨부한 후 질문합니다. 샘플 프레임은 `<출력 디렉터리>/<프로젝트명>/샘플프레임/`에 저장합니다.
4. 사용자가 조합(예: "A의 색감 + C의 캐릭터")을 원할 경우 이를 반영하여 기록합니다.

## 2라운드: 세부 사항 확정

| id | 질문 | 대표 선택지 |
|---|---|---|
| assets | 소재 저작권 경계 | 관대한 규정: 자체 소재 + AI 생성 이미지 + 상업용 음악, 타사 로고는 참조용으로만 사용(추천) / 엄격: 타사 로고 배제, CC0 음원만 사용 / 전적인 사용자 책임 |

| screens | 실제 스크린샷 출처 | 공개 웹페이지 + 커뮤니티/문서 내 작업물 이미지(추천: 확보 가능한 장수를 먼저 집계하여 안내) / 로그인이 필요한 페이지: 브라우저 창에서 사용자 로그인 지원 / 사용자가 직접 스크린샷이나 화면 녹화 제공 |
| music | 배경음악 | 3~4개의 30초 샘플 청취 후 선택, 또는 선호 장르(일렉트로닉 / 펑크 / 서사시적 웅장함 / 경쾌한 팝 등) 질의 / 사용자가 음원 직접 제공 |
| cta | 웹사이트 주소 및 CTA | 표시할 URL, 노출 위치(최소 클라이맥스 1회 + 엔딩 1회), 버튼 문구 |
| credit | 제작자/브랜드 보증 | 중점 강조 / 가볍게 언급 / 노출하지 않음 |
| web | 웹 플레이어 버전 | 로컬 구동(우선 추천) / EdgeOne Pages, Vercel 배포 / 기존 웹사이트 임베드 |
| review | 중간 검토 방식 | 요구사항 확정 후 전 과정 자동 완료 후 납품(기본값) / 러프컷 1차 검토 후 디벨롭 / 정지 프레임 스토리보드 선검토 |
| export | 내보내기 규격 | 4K60 + 1080p60(추천) / 1080p60 / 4K30 |

마지막 질문은 항상 다음으로 고정합니다:
