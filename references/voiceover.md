# 더빙 및 내레이션 (ElevenLabs 보이스오버)

사용자에게 ElevenLabs 계정이 있는 경우 홍보 영상에 내레이션을 기본 포함합니다. 제품을 처음 접하는 사람도 '소리'만 듣고 핵심을 따라올 수 있도록 하기 위함입니다. 단일 명령어로 전체 생성되며 2단계 자동 검증이 진행됩니다. AI는 소리를 직접 들을 수 없으므로, **모든 판단은 텍스트 변환(STT) 일치율과 음압 레벨 측정에 기반**합니다.

## 1. 사전 준비

- 공식 스킬 설치: `npx skills add elevenlabs/skills@text-to-speech -g -y` (작곡 및 효과음은 `references/music-and-beats.md` 6절 참조).
- API 키를 작업공간 루트의 `.env`에 `ELEVENLABS_API_KEY=...` 형태로 입력하거나 환경변수로 등록합니다. 채팅창에 키를 직접 노출하지 마세요. `python3 scripts/elevenlabs.py quota`로 플랜 및 사용량을 조회합니다.
- 기본 권장 모델은 `eleven_v4`입니다 (자연스러운 발음 품질 제공). 단, **v4 모델은 speed 및 style 조절을 지원하지 않으므로**, 말의 빠르기를 조절할 수 없어 문장별 글자 수를 철저히 통제하여 지정된 타임윈도우 안에 안착시켜야 합니다.

## 2. 음색(Voice) 선정

`python3 scripts/elevenlabs.py voices`로 계정 내 보이스와 추천 보이스 라이브러리를 조회합니다.

1. **제품 제작자/브랜드 대표 본인의 클론 보이스가 있는지 먼저 확인**합니다 (카테고리가 `professional` 또는 `cloned`인 항목). 있다면 청취 후보에 포함하되 **기본값으로 무조건 쓰지는 마세요**: 본인 복제 음성은 억양이 어색하거나 발음이 뭉개지는 경우가 종종 발생합니다. 라이브러리 검증 음성과 비교 청취 후 결정합니다.
   - `elevenlabs.py vo` 실행 전 학습 상태를 자동 조회합니다. 모델별로 훈련되지 않은 경우 에러를 방지하기 위해 다음 전략을 취합니다:
     - **훈련 완료된 `eleven_multilingual_v2` 사용**: 속도/스타일 조절 가능. 단, 고유명사나 브랜드명 발음 주의.
     - **`eleven_v3` 생성 후 음성 변환(STS)으로 본인 음색 입히기** (`voice.model: "eleven_v3"`, `voice.sts: true`): 발음 정확도와 본인 음색을 동시에 충족.
     - 클론 보이스는 안정성(stability)을 0.85 수준으로 높이고 `--takes 4` 옵션으로 복수 생성 후 가장 정확한 결과물을 자동 채택합니다.
2. 그렇지 않은 경우 3가지 후보(광고/내레이션 톤, 정확한 표준 발음, 콘셉트에 부합하는 연령대)를 선정하여 대표 문장 3개로 테스트합니다:

```bash
python3 scripts/elevenlabs.py vo --voice <voice_id> --out /tmp/vo-<이름> --only hook,brand,cta
```

3. 객관적 비교: 텍스트 일치율(1.00 권장), 필요한 배속 배율(1.0에 가까울수록 기계음이 적음), 잔여 시간 여유. 비교 결과와 샘플 파일을 사용자에게 전달하여 결정하도록 합니다.
4. 청취 파일 생성: 각 음성별로 대표 3문장(오프닝 훅, 정보 집중 문장, 클라이맥스)을 하나로 이어 붙이고 -16 LUFS로 노멀라이즈합니다:

```bash
ffmpeg -i /tmp/vo/hook.mp3 -i /tmp/vo/clues.mp3 -i /tmp/vo/climax.mp3 \
  -filter_complex "[0][1][2]concat=n=3:v=0:a=1,loudnorm=I=-16" "out/音色候选/A-음색명.mp3"
```

**샘플 청취를 먼저 하고, 본 대본을 작성하세요**: 음색이 변경되면 발화 속도와 씬별 타임윈도우가 모두 달라져 전체 타임라인을 다시 계산해야 합니다.

## 3. 내레이션 대본 작성

`src/timing.json`의 `voice.lines`에 작성하며, 씬마다 한 문장씩 배정합니다:

```json
{"id": "cta", "at": 50.3, "end": 56.6, "text": "지금 바로 example.com에서 무료로 시작하세요!", "say": "지금 바로 example 점 com에서 무료로 시작하세요!", "duckDb": -14}
```

- `at`: 발화 시작 시점 (스크립트가 무음 구간을 트림하므로 첫 음절이 정확히 `at`에 위치함). `end`: 발화 종료 마감 시점. 보통 씬 시작 0.3~0.4초 후 발화하고 씬 종료 0.1~0.2초 전에 마칩니다. 비트 폭발 강타 후에는 0.3초 여유를 두고 말하기 시작합니다.
- **글자 수 예산**: 한국어 일반 광고 내레이션 속도는 초당 약 3.5~4.5음절(쉼표 호흡 포함)입니다. 4초 씬에는 약 14~18자, 8초 씬에는 30자 내외가 적당합니다. 글자 수가 초과하면 대본을 과감히 줄이세요 (스크립트 자동 가속은 최대 12%까지만 권장).
- **화면 자막과 내레이션의 상호 보완**: 화면에 이미 크게 노출된 긴 문구는 내레이션에서 생략하고, 내레이션은 전체 흐름을 매끄러운 구어체로 엮어주는 역할을 합니다.
- 호흡 구간 유지: 빠른 컷 전환 직후나 클라이맥스 직전에는 1~2초간 말을 멈추고 음악만 웅장하게 울리도록 여백을 둡니다.
- **브랜드명과 URL은 `voice.keywords`에 등록**: 키워드 목록에 등록된 단어가 하나라도 누락되거나 왜곡되면 자동으로 `CHECK_WORD` 플래그가 발생하여 재검토를 유도합니다.
- `say` 필드: TTS 엔진이 발음하기 좋게 한글 표기로 다듬은 텍스트 (예: 숫자 "77" → "칠십칠", URL "codefather.com" → "코드파더 닷컴"). `text` 필드: 원본 자막 텍스트.

## 4. 음성 생성 및 자동 검증

```bash
python3 scripts/elevenlabs.py vo        # 변경된 문장만 생성하고 나머지는 캐시 재활용
```

검증 플래그:
- `OK`: 시간 제한 충족 및 텍스트 변환 일치.
- `TOO_LONG`: 1.12배 가속으로도 시간 초과. 문장을 줄이거나 씬 길이를 연장해야 함.
- `CHECK_TEXT`: 텍스트 불일치(유사도 < 0.85). 발음 교정을 위해 `say` 수정.
- `CHECK_WORD`: 핵심 브랜드명이나 URL 누락.
- `ECHO`: 음성 끝부분의 잔향이 250ms를 초과하여 에코 현상 발생 위험. 모델이나 음색 변경 필요.

## 5. 오디오 믹싱

`mix.py`에서 `duck_curve`를 통해 발화 구간에 BGM 볼륨을 자동으로 낮춥니다:

- 기본 권장값: `rmsDb: -13`, `duckDb: -9` (페이드 0.08초, 복원 0.35초). 가장 중요한 CTA 문장은 `duckDb: -14`로 더 깊게 누릅니다.
- `mix.py` 실행 시 출력되는 `vo_margin`(음성이 음악보다 얼마나 큰지)이 **모든 구간에서 반드시 ≥ +8 dB**를 유지해야 합니다.
- 믹싱 완료 후 전체 최종 검증 실행:

```bash
python3 scripts/elevenlabs.py check-mix    # 믹싱된 완성 오디오의 STT 검증, 일치율 ≥ 0.97
```

## 6. 음색 변경 및 대본 수정 시 워크플로우

영상 비주얼 렌더링을 다시 할 필요 없이 오디오만 빠르게 교체합니다:

```bash
python3 scripts/elevenlabs.py vo && npm run mix && python3 scripts/elevenlabs.py check-mix
ffmpeg -i out/final-4k.mp4 -i public/audio/mix.wav -map 0:v -map 1:a -c:v copy -c:a aac -b:a 320k -shortest out/final-4k-신규오디오.mp4
```

## 7. "에코/하울링이 들린다"는 피드백 발생 시 점검 순서

1. **재생기가 2개 이상 동시에 켜져 있는지 확인**: 브라우저 탭, MP4 플레이어, 테스트 창 중복 재생 여부 점검.
2. **영상 파일 내 오디오 트랙이 1개인지 확인**: `ffprobe`로 스트림 개수 확인.
3. **음성 자체의 잔향 확인**: `report.json`의 `tail_ms` 확인 (200ms 이하가 정상).
4. **BGM 트랙 자체에 음성이 섞여 있는지 확인**: 배경음악 단독 STT 점검.
5. **웹 플레이어의 오디오 스케줄링 충돌 여부 확인**.

## 8. 라이선스 및 크레딧

ElevenLabs 유료 플랜 생성물은 상업적 이용이 가능하며 출처 표기가 면제됩니다. 무료 플랜 생성물은 상업적 이용이 불가하므로 유의하세요.
