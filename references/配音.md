# 配音（ElevenLabs 旁白）

用户有 ElevenLabs 账号时，默认给宣传片配旁白：让没看过产品的人「听」也能跟上。全流程一条命令生成 + 两道自动校验，AI 听不到声音，所以**所有判断都靠转写和电平测量**。

## 1. 准备

- 装官方 skill：`npx skills add elevenlabs/skills@text-to-speech -g -y`（作曲、音效见 `音乐与卡点.md` 第 6 节）。
- key 写进工作区根目录的 `.env`（照 `.env.example`，`ELEVENLABS_API_KEY=...`）或设成环境变量，所有项目通用；不要让用户贴进聊天。`python3 scripts/elevenlabs.py quota` 看套餐和额度。
- 模型默认 `eleven_v4`（中文好、最自然）。**v4 不支持 speed 和 style**：语速没法调，只能靠控制字数让每句装进时间窗。

## 2. 选音色

`python3 scripts/elevenlabs.py voices --zh` 列出账号里的音色和音色库里的中文热门音色。

1. **先看账号里有没有产品作者 / 品牌方本人的克隆音色**（`voices` 列表里 category 是 `professional` 或 `cloned` 的）。有就放进试听候选，但**不要默认直接用**：Claude Fable 5.5 一片全片用了作者本人的克隆音色，用户听完说「很多音调都有点怪」，换成音色库的 Haoran 后才满意；同一份稿子，克隆音色混音转写 0.968，Haoran 是 1.000。专业克隆音色要按模型分别训练，状态不是 `fine_tuned` 时会返回 `voice_not_fine_tuned`，此时先用音色库音色，等训练完把 `voiceId` 改回去重跑即可（见第 6 节）。
   - `elevenlabs.py vo` 开跑前会自动查训练状态（`GET /v1/voices/<id>` 的 `fine_tuning.state`），没为当前模型训练就退出，并列出已训练的模型。v4 没训练、其他模型训练好了，有两条路：
     - **换成已训练的 `eleven_multilingual_v2`**（支持 `speed`、`style`）。普通中文最稳，但**品牌名会连读**：鱼皮 AI 导航一片里「鱼皮 AI」被连读成「pai」，听起来是「鱼排」，加逗号、引号、拆字母、分段生成都没救；句尾混响拖尾 90~360 ms，用户听出「回音」。
     - **`eleven_v3` 读 + 转回本人音色**（`voice.model: "eleven_v3"`、`voice.sts: true`）。v3 没为克隆音色训练，直接用时读音准、拖尾只有 40~110 ms，但用户说「声音和我的不太一样了」；脚本会再用已训练的 `eleven_multilingual_sts_v2` 把每句转回本人音色。鱼皮 AI 导航最终用的这条，12 句转写全部正确。
     - 选哪条看稿子：有品牌名、英文缩写和中文连在一起的（「鱼皮 AI」「面试鸭 App」），直接走第二条；纯中文稿走第一条。不管哪条都要在 `voice.keywords` 里列出品牌名和网址（见第 3 节）。
   - 对比模型不用改 timing.json：`vo --model eleven_flash_v2_5 --out /tmp/vo-flash --only hook,cta`。面试鸭对比过 multilingual_v2、turbo v2.5、flash v2.5：flash 偶尔最准，但同一句每次生成差异最大；multilingual_v2 配高 stability 最稳。
   - 克隆音色咬字不如音色库音色稳：面试鸭一片的克隆音色在 multilingual_v2 上 stability 0.5 时「一万多道题」被听成「一模多刀」，调到 **0.85** 才稳定。生成时加 `--takes 4`：每句最多生成 4 条，留转写最准的那条。
2. 否则挑 3 个候选（广告 / 旁白类、普通话标准、和风格相符的年龄性别），用最有代表性的 3 句试：

```bash
python3 scripts/elevenlabs.py vo --voice <voice_id> --out /tmp/vo-<名字> --only hook,brand,cta
```

3. 客观比较：转写匹配度（都应是 1.00）、**需要的加速倍数**（越接近 1.0 越好，加速多了有机械感）、时长余量。把试听文件和比较结果给用户；用户说「你来定」时选语速最贴合时间窗的那个，并写进需求确认。
4. 试听文件的拼法：每个音色把 3 句代表句（开场、信息最密的一句、高潮）串成一个文件，统一到 -16 LUFS，文件名写音色特点：

```bash
ffmpeg -i /tmp/vo-haoran/hook.mp3 -i /tmp/vo-haoran/clues.mp3 -i /tmp/vo-haoran/climax.mp3 \
  -filter_complex "[0][1][2]concat=n=3:v=0:a=1,loudnorm=I=-16" "out/音色候选/A-Haoran（低沉稳重·广告）.mp3"
```

**先试听、后写全稿**：音色定了再生成全部句子。整片生成完才换音色，所有句子的时长都会变，要重新排时间窗。

**换模型也算换音色**：同一个 `voiceId` 换了模型（v2 → v3）或加了转音色，音色就会变。鱼皮 AI 导航为修读音换成 v3，转写全对就直接重混交付了，用户第一句反馈是「声音和我的不太一样了」。所以只要改了模型、`settings` 或 `sts`，都先出 3 句试听让用户确认，再全量生成。

编程导航用的是 Haoran（`pU9NaAwkoR3v0Mrg3uKz`，音色库「广告」类，低沉有磁性）：三个候选里只有它的开头句不用加速。

## 3. 写旁白稿

写进 `src/timing.json` 的 `voice.lines`，每句一个场景：

```json
{"id": "cta", "at": 50.3, "end": 56.6, "text": "…现在就上 codefather.cn，免费开始！", "say": "…现在就上 codefather 点 C N，免费开始！", "duckDb": -14}
```

- `at` 是开口时刻（脚本会切掉首尾静音，所以第一个字就落在 `at`），`end` 是最晚收尾。一般在场景开始后 0.3~0.4 秒开口、场景结束前 0.1~0.2 秒收住；爆发重拍后 0.3 秒再开口，别和重击抢。
- **字数预算**：v4 中文广告语速约 5~6 字/秒（含标点停顿）。4.36 秒的场景装 14~18 个字；8 秒快切装 30 字左右。超了就删字，不要指望加速（脚本最多自动加速 12%）。
- **说的和屏幕上的互补，不逐字重复**：屏幕上已有的长句可以省掉（编程导航把「一站搞定」从旁白里删了），旁白负责把画面串成一句话。点名的项目、数字都必须是画面里真的出现、调研笔记里有出处的。
- 开场旁白跟着开场情绪：痛点段用问句（「从哪开始学？项目没亮点？面试总卡壳？」）。breakdown 那种音乐抽空的地方正好放一句关键的话。
- 留呼吸：快切之后、高潮之前留 1~2 秒不说话，让音乐出来（编程导航的项目墙 2 秒没有旁白）。
- **品牌名和网址写进 `voice.keywords`**（如 `["鱼皮", "codefather"]`，按你的产品换成品牌名和网址主体）。整句相似度会放过关键的错字：网址句听成「语牌 AI 导航，ai.codefather.cn」，相似度 0.90，照样判 `OK`，可错的正是品牌名。列进 `keywords` 后，转写里少一个就判 `CHECK_WORD`，`check-mix` 也按它检查成品混音。
- **句首短叠词经过转音色容易糊**：「试试鱼皮 AI 导航！」v3 原声转写是对的，转成本人音色后连续 4 条都成了「设置 / 这是 / 就是鱼皮 AI 导航」；改成「快来试试，鱼皮 AI 导航！」一次通过。句子开头留一个引导字，品牌名前加逗号。
- `say` 是实际送给 TTS 的文字，`text` 是稿子原文：数字写成汉字（「七十七期」）；网址、英文缩写拆开写（「codefather 点 C N」，大写字母在音乐下最容易听清）。
- 避开转写反复出错的词：同音字（「面经/面镜」「鸭/呀」）可以不管，但真念不清的词要换说法。面试鸭一片里「大厂」被听成「大汉」、「保精度」被听成「报警盾」、「对比着学」被听成「对比招学」，换成「真题」「又快又准」「看懂区别」后都是 1.00。
- 时间窗特别短（< 2.2 秒）的句子很难稳定装下，每次生成的语速都有波动。和相邻句合并成一句（编程导航把「数千位同学已拿到 Offer」和网址句合成了一句）。
- **夹英文、数字的句子语速更慢**：Haoran 念纯中文约 5 字/秒，夹着「Fable 5.1」「Tibo」时只有 4~4.3 字/秒。这类句子按 4 字/秒算预算（英文单词、「五点一」都按 2~3 字计）。超时就删「验证方法是」「自己」这类虚词，屏幕上已有的信息（日期、「不联网」）从旁白里删掉。
- **听错了会变成错误事实的词，必须改掉**，不能当同音字放过：「一上线」被听成「已上线」（变成「Fable 5.5 已上线」）、「五点五一正式发布」被听成「5.51」、「最炸」被听成「最渣」。改成不会歧义的说法：「等它正式发布」「最绝的是」。数字后面不要紧跟「一」「已」开头的词。
- **克隆音色容易念糊的**：句尾的「五点五」（多次被听成「无电雾」）、「路由」（「绿油」）、「十月」（混进音乐后成了「日月」）、「暗号」（「然后」）。用克隆音色时这些位置换说法，或者干脆不念、交给屏幕。

## 4. 生成与校验

```bash
python3 scripts/elevenlabs.py vo        # 全部生成；文字、音色、模型没变的句子走缓存，不重复扣额度
```

每句会：生成（带上前后句做上下文衔接，v3 不支持这个参数会自动跳过）→ 开了 `sts` 就转回本人音色 → 切首尾静音 → 超时就加速（≤ 1.12）→ Scribe 转写比对 → 量句尾拖尾。输出：

- `OK`：时长装得下，转写和稿子一致。
- `TOO_LONG`：加速到 1.12 还装不下，删字或放宽时间窗。
- `CHECK_TEXT`：转写对不上（匹配 < 0.85）。对照「听到的」改 `say`。阿拉伯数字和汉字数字已经自动换算，不会误报。
- `CHECK_WORD`：`keywords` 里的品牌名、网址没听到。先重跑（会自动重新生成），还不行就按第 2 节换模型，或在品牌名前后加逗号。
- `ECHO`：句尾从峰值 -20 dB 衰减到 -45 dB 超过 250 ms，在音乐下会像回音。换模型（v3 + `sts`）或换音色。

全部 `OK` 才进入混音。结果在 `audio-src/vo/report.json`。直接重跑 `vo` 时，上一轮没通过的句子（`TOO_LONG` 除外）会自动重新生成，通过的走缓存；`--takes 4` 的多条择优在转音色**之后**挑，因为转音色本身也会读错。

**不要绕开 `vo` 另写生成脚本**。鱼皮 AI 导航的工程是在模板加入 `vo` 之前复制的，第一次配音用了自己写的 `tts.py`，只量时长、没转写，「鱼皮」读成「鱼排」是用户听出来的。工程里没有 `scripts/elevenlabs.py` 就先从 `<工具目录>/template` 拷过来（见 AGENTS.md 第 10 步「改版」）。

## 5. 混音

`mix.py` 里：`voice_lines(TM, rmsDb)` 读取并统一每句响度，`duck_curve(...)` 生成「说话时压低音乐」的增益曲线，音乐 `place(..., duck=duck, tag="music")`，旁白 `place(..., tag="voice")`。模板的 `mix.py` 已经写好。

- 默认 `rmsDb: -13`、`duckDb: -9`（起压 0.08 秒、恢复 0.35 秒）。最重要的那句（网址 / CTA）单独设 `duckDb: -14`，同时刻的高频音效（闪光、彩纸）减半。
- `mix.py` 运行时会打印 `vo_margin`：每句人声比音乐高多少 dB，**要求全部 ≥ +8 dB**。编程导航最初用 -18 / -7，高能段人声只高出 1~2 dB，会被音乐盖住。
- 混完必跑：

```bash
python3 scripts/elevenlabs.py check-mix    # 转写成品混音，整体匹配 ≥ 0.97 且每句都听得到
```

整体匹配差一点到 0.97 时，把转写和稿子逐字对比：剩下的差异如果全是同音字（它/他、接头/街头），可以接受，但要在调研笔记里列出来；只要有一处会让意思变（已/一、渣/炸、数字），就必须改稿重生成。

单独听清不代表混进去也听清：编程导航的网址单独转写是「codefather.cn」，混进音乐后成了「点 CM」。加深那一句的 duck、减弱同时刻的闪光音效、改成大写「C N」后才稳定。

**先排除转写误差，再动混音。** 整片转写每次结果都不一样，一句没听清不代表混音有问题。`check-mix` 会把没听清的句子自动截出来再转写两次：两次都对，就只是整片转写的误差，不用改。两次都错才去找原因，而且**改之前先做对照**（同一段，改前改后各转写 3 次）。面试鸭踩过这个坑：「再精挑」在混音里被听成「带金条」，当时以为是 riser 音效盖住了人声，就删了音效。事后做对照发现，加不加 riser，3 次转写都是对的；真正起作用的是同时重新生成了一条咬字更清楚的录音。所以：
- 确实没听清时，**先重新生成那一句**（删掉 `raw/<id>.mp3`，`vo --takes 4`）或换个说法，这一步最常见也最有效。
- 再怀疑音效。`vo_margin` 只比较人声和音乐，不算音效，但实测全频或 1.5~5 kHz 频段的人声余量都分辨不出 riser 的影响，要靠对照转写判断。和开口第一个字同时刻的砸字音效还是建议压轻。

## 6. 以后换音色 / 改稿

只动音频，画面不用重渲染：

```bash
# 改 timing.json 的 voice.voiceId 或某句 text/say
python3 scripts/elevenlabs.py vo && npm run mix && python3 scripts/elevenlabs.py check-mix
ffmpeg -i out/final-4k.mp4 -i public/audio/mix.wav -map 0:v -map 1:a -c:v copy -c:a aac -b:a 320k -shortest out/final-4k-新音轨.mp4
```

`at` / `end` 改了才需要确认画面节奏；场景时间没变就直接换音轨。

第一次加旁白时，把原来的无旁白版保留下来当「纯音乐版」（`宣传片 4K 纯音乐.mp4`），方便用户对比、也能用在不适合出声的场合。之后再改音乐时用 `python3 scripts/mix.py --no-vo` 生成 `out/mix-music.wav`，同样换进成片即可。

## 7. 用户说「有回音 / 两个人在说」时怎么查

AI 听不到，按下面顺序用数据排除，**先确认问题在文件里还是在播放器里**：

1. **是不是开了两个播放源**：网页版 + MP4、多个浏览器标签页、没关的测试页。给用户「运行」时只打开一个播放源。
2. **文件里有没有第二份人声**：`ffprobe` 数音轨（应为 1）；把旁白分轨和成品混音做互相关，除了 0 ms 以外不应有超过 0.1 的峰（编程导航实测最高 0.02）。
3. **人声自带混响**：看 `audio-src/vo/report.json` 每句的 `tail_ms`（`vo` 自动量）。干声 < 200 ms；鱼皮 AI 导航一片的克隆音色在 multilingual_v2 上 90~360 ms，用户就说「人物有回音」，v3 + 转音色后 20~110 ms 才不再提；Shan Shan 约 500 ms。超过 250 ms 脚本判 `ECHO`，换模型或音色。别指望 ElevenLabs 的「人声分离」（Audio Isolation）事后去混响：它要求音频 ≥ 4.6 秒，单句旁白直接 400 报错。
4. **配乐里有人声**：用 `elevenlabs.py stt audio-src/music.mp3` 转写配乐，应该只有 `[背景音乐]` 一类标签、没有文字。
5. **播放器**：以上都正常，问题就在网页播放器。编程导航遇到了两层：`@remotion/media` 的 Web Audio 分块被反复排程（约 6 份叠加），以及 Player 为等画面把声音往回拉（半句被重播）。模板的 `web/App.tsx` 已改成「`<audio>` 当时钟、画面跟着声音走」，验证方法见 `校验清单.md` 的网页版一节。

MP4 成片没有这个问题：音轨是直接封装进文件的，播放器不会重新排程。
